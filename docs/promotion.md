## 一、环境检测结果（模拟器不可用，已改用真机录制）

检测时间：2026-11-21。

| 项目 | 结果 |
| --- | --- |
| 模拟器可执行文件 | `C:\Users\33558\Documents\deepseek-harness\default-workspace\out\sdk\emulator\emulator.exe` |
| 模拟器版本 | Android emulator 37.2.13.0（build 16740729） |
| `emulator -accel-check` | `accel: 0`，`WHPX(10.0.26300) is installed and usable` |

| 系统版本 | Microsoft Windows 11 家庭版 中文版 |
| CPU | Intel Core Ultra 7 251HX；`Win32_Processor` 报告 `VirtualizationFirmwareEnabled=False`、`VMMonitorModeExtensions=False` |
| 虚拟化占用 | `Win32_DeviceGuard.VirtualizationBasedSecurityStatus=2`，`SecurityServicesRunning={2}` → **内核隔离（内存完整性 / VBS+HVCI）正在运行并占用 VT-x** |
| 系统可选功能 | `VirtualMachinePlatform`、`HypervisorPlatform` 均为「已禁用」；家庭版无法开启 WHPX/Hyper-V |
| 当前权限 | 普通用户（`isAdmin=False`），安装 AEHD 驱动需 UAC |

结论与实测：**本机无法运行 Android 模拟器**。

1. WHPX 虽然报告「可用」，但 guest vCPU 实际不执行：qemu 进程存活 1–2 分钟后 CPU 时间仅 ~0.4s，随后静默退出，Windows 事件日志记录 `crashpad_handler.exe` 异常 `0x80000003`。
2. 回退到纯软件模拟（`-accel off`）同样失败：`-gpu off -no-window`、`-gpu guest` 直接退出，日志末尾只有 `Exited a loader RenderThread`。
3. 要做成这件事，必须先由管理员：① 关闭「内核隔离 → 内存完整性」并重启；② 安装 AEHD（Android Emulator Hypervisor Driver，需要 UAC）。

因此本次宣传片素材**全部在真机上录制**（用户授权借用手机）：
`25113PN0EC`（Xiaomi，Android 17），屏幕 1220×2656，density 520，安装的是 Smath 1.4.0 release（versionCode 12）。
录制命令：`adb shell screenrecord --bit-rate 16M --time-limit <秒> /sdcard/rec.mp4`，`adb pull` 取回。
注意：该机型自带的 `screenrecord` **不接受 `--bitrate`**（只接受 `--bit-rate`），传错参数会直接不产出文件。

### 重录/补拍提示

- **双指缩放**：`adb shell input` 不支持多点触控，`sendevent` 写入 `/dev/input/event7` 被 SELinux 拒绝（`Permission denied`），因此 `05-drawing.mp4` 只有**平移**、没有缩放。若要缩放镜头，需要人工两只手指或另录一段。
- 录屏无音频：成片统一用 BGM + 屏幕文字，旁白可选后期配音。
- 真机状态栏（时间/信号/电量）会入镜：后期在 16:9 画布上把竖屏画面缩到 78% 并加圆角/阴影即可自然遮挡。
- 若以后模拟器可跑（关闭内存完整性 + 装 AEHD），用 `smath_phone` AVD 可重录 1080×2400 干净素材：`emulator -avd smath_phone -gpu swiftshader_indirect -no-snapshot -no-boot-anim`。
- 画幅：主片 16:9，素材是竖屏 1220×2656，合成时以「手机浮在舞台中央」呈现，比硬裁更稳。

## 三、宣传片构思

### 定位

一句话：**“不止会聊天，还会画图、会算、会讲题的数学 AI 学习搭子。”** 主角不是模型参数，而是「把一道题真正讲清楚」的过程。

情绪曲线：**卡住 → 被理解 → 顺畅 → 惊喜（会画会算）→ 安心（数据在本机）→ 品牌**。
全片不出现真人、不出现“参数/跑分”，只拍屏幕和字。

### 版本规划

| 版本 | 时长 | 画幅 | 用途 |
| --- | --- | --- | --- |
| 主片 | 60s | 16:9 横屏 1080p | 官网页头、GitHub Release 说明、B 站/YouTube |
| 竖屏短片 | 30s | 9:16 1080×1920 | 抖音 / 小红书 / 视频号（主片精简版，见“竖屏短片”一节） |
| 社交方图 | 静帧（可加 6s 循环动效） | 1:1 1080×1080 | GitHub Social Preview、公众号头图 |

### 逐镜导演笔记

**1｜痛点（0–7s）**
- 背景纯黑 `#000000`，公式用 LaTeX 渲染成白色，字号大到占满屏宽。
- 第 0.6s 公式右侧被一条硬边裁掉，同时浮出「已到当前时段额度上限」，字距略松、轻微抖动 2 帧后停住。
- 旁白文字在左下角，小字、65% 灰，和公式形成“冷 / 更冷”的层次。
- 声音：只有极轻的低频嗡声和一次“信号中断”的短促电流声，不加音乐，制造不适。

**2｜预设（7–13s）**
- 舞台化为浅灰 `#F7F8FA`，手机以竖屏姿态悬浮在画面右侧 1/3，左侧留白放旁白。
- 五个预设卡片从卡片中心“点亮”，选中「数学问题」时边框变品牌蓝 `#4D6BFE`、图标轻微弹一下。
- 转场：第 1 镜的方程硬边，作为第 2 镜卡片边缘的遮罩推开（同形状转场）。

**3｜提问与思考（13–20s）**
- 输入框打字用“逐字出现 + 光标跟随”，不要用整段粘贴，观众要看到“人在输入”。
- 点发送后，思考条以 200ms 淡入并折叠成一行小字，末尾用省略号呼吸动画表示仍在思考。
- 旁白：“先思考，再解答。”——这句话留给画面自己说，不叠加任何音效。

**4｜长公式（20–30s）**
- 这是全片唯一一次完整展示“回答”，镜头从答案顶部缓慢下滚，速度约 40px/s。
- 滚到超长公式时停住，手指入画按住公式向右拖两次（第一次露出一半，第二次到底），公式左缘出现极淡的渐隐，暗示“可继续滑”。
- 在“关键变形”那一行高亮：蓝色下划线从左到右生长 400ms。
- 旁白文字放在公式下方 24px，避免遮挡公式本体。

**5｜绘图（30–39s）**
- 切到绘图块时，`function("sin(x)")` 的曲线用“从左向右生长”的绘制动画（0.8s），比直接出现更有生命力。
- 双指缩放进、坐标轴刻度随缩放变化，网格线在缩放过程中保持 1px 的细度（模拟真实坐标纸）。
- 镜头轻微推近画布中心，幅度不超过 8%，模仿苹果产品镜头的“呼吸感”。

**6｜计算器（39–45s）**
- 计算器块展开用的是“上盖打开”式的高度动画（240ms，ease-out），不是弹窗。
- `(3+4i)*(2-i)` 的输入逐字出现，结果行用品牌蓝底、白字，最后 0.3s 数字做一次轻微 scale 1.0→1.04→1.0。
- 旁白呼应：“模型可以调用计算器 agent 来验算自己的结果。”

**7｜设置（45–53s）**
- 画面切到设置页，镜头从“模型和 API Key”标题缓慢下移到 Key 输入框；Key 全程打码，只露出前 3 位。
- 切一次模型（DeepSeek → ChatGPT），列表项高亮跟随，强调“模型自己选”。
- 旁白：“模型自己选，Key 只留本机。”——这句话是全片的信任锚点，停留 1.5s 再转场。

**8｜落版（53–60s）**
- 背景回到品牌蓝 `#4D6BFE`，与第 2 镜高亮色、第 6 镜结果底色形成同一根线索。
- 图标以 0.6 缩放淡入，标语「Smath · 开源」用大字重居中；**不放仓库地址、不放二维码**，保持画面干净。
- 第 57s 起，图标与标语轻微上移 2%，留出一段纯蓝收尾；最后一帧不再出现新元素。

### 视觉与音乐

- 主色沿用应用品牌蓝 `#4D6BFE`，背景用浅灰 `#F7F8FA`，深色模式镜头各占一半，形成节奏对比。
- 转场：同形状遮挡（圆角卡片放大成下一镜背景），避免花哨 3D。
- 音乐：让用户自己加
- 字幕：思源黑体 Bold，白字深色描边；公式镜头不叠字幕，让 LaTeX 自己说话。
- 不 tts，旁白放在旁边
- 模仿苹果宣传片的风格

补充执行细则（配合以上五条）：

- **苹果风的具体手法**：大留白、单一光源、产品（手机画面）带 24–40px 柔和投影、镜头运动只用缓入缓出、每镜只讲一件事、文字出现用“蒙版上推”而不是缩放。
- **旁白排版**：统一放画面左侧（竖屏版放底部安全区上方），字号为画面高度的 3.2%，行高 1.5，最多两行；出现方式为逐行淡入，每行停留 ≥1.8s，确保静音观看也能读完。
- **字幕**：只对屏幕上的 UI 文案做轻描边，不重复旁白文字；公式镜头保持画面干净。
- **配色切换**：第 1 镜纯黑 → 第 2–6 镜浅色 → 第 7 镜深色 → 第 8 镜品牌蓝，用背景色的四次变化做章节感。
- **音乐接口**：剪辑时间线预留一条 `music` 轨（44.1kHz 立体声），在 20s、30s、39s 三个 Wow 点标好节拍标记，方便用户后配音乐时对齐；若最终无音乐，保留环境音与 UI 音效即可成片。
- **音效**：点击 `tap`、发送 `whoosh`（短）、公式拖动 `soft slide`、绘图生长极轻的 `draw`，音量统一压到 -18dB 以下，不与音乐抢。

1. **痛点素材**：黑底 + 一段被裁切的 LaTeX 公式 + 「已到当前时段额度上限」文案（可在剪辑软件里做，不必录屏）。

### 录制与后期流程

1. AVD 内安装 `app-release.apk`，用真实 API Key 提前跑好两条会话，避免现场等流式输出。
2. `adb shell screenrecord --size 1080x2400 --bitrate 12M --time-limit 180` 分段录制，每段只做一个动作。
3. `ffmpeg` 裁剪 + `setpts` 做 0.6×/1.6× 变速，关键动作处加 4 帧缓入缓出。
4. 片头片尾用同一套圆角卡片做模板；屏幕文字在剪辑软件里重新排，避免录制分辨率下的锯齿。
5. 导出：H.264 / 1080p / 30fps / CRF 18，音频 AAC 192k。

执行顺序与命名建议：

1. **准备**：装 APK → 配好 Key → 选「数学问题」预设 → 开启绘图 Agent → 发一条会触发超长公式和绘图块的题 → 等回答完全结束（避免录制中继续流式输出）。
2. **分段录制**：每条素材单独录，文件命名 `01-pain.mp4`、`02-presets.mp4`……`08-endcard.mp4`，方便对号入座。
3. **粗剪**：按分镜表时长拼到 60s 时间线，先只对“动作起点”，不管字。
4. **精修**：加旁白文字、屏幕文字、投影与背景色切换；把竖屏素材放进 16:9 舞台（居中、带阴影、必要时 1.05× 推近）。
5. **动效**：公式横向拖动与绘图生长两处做 0.8× 慢放，其余保持原速。
6. **混音**：留 `music` 空轨；若加音乐，在 20s / 30s / 39s 卡点；音效压到 -18dB 以下。
7. **导出与归档**：`Smath-promo-60s-1080p.mp4`，同时导出 `Smath-promo-30s-vertical.mp4`；工程文件与素材按 `promo/YYYYMMDD/` 归档。
