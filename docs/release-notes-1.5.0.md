## 1. 多步工具调用（核心改动）

以前一次提问只有一次模型调用：模型写出工具块，应用渲染结果，回答就结束了——模型本身看不到自己算出来的东西，只能继续靠推测往下写。

1.5.0 把这条链路改成多步往返：

1. 模型在思考/回答中写出工具块后，按协议**立刻结束本轮输出**；
2. 应用扫描出已闭合的工具块，在本地真正执行一次（计算器、绘图、线性代数）；
3. 执行结果作为一条「工具执行结果」消息回灌给模型，再发起下一轮请求；
4. 模型看到真实结果后继续推导，最多往返 4 轮。

因此像"先算出系数、再写成因式分解、再代回验证"这类任务，模型现在能拿到每一步的真实数值，而不是凭空编造。回答下方的提示条会显示本轮共调用了多少次工具。

对应的系统提示词也新增了《多步工具调用》协议：写完工具块就停、收到结果不要重复输出、每轮只调一个工具、不许编造结果、报错要修正重试。

## 2. 线性代数计算器 Agent

新增内置符号计算引擎（纯 Kotlin、精确有理数运算，无第三方依赖、无网络），支持 13 个命令：

`det` `rank` `inv` `rref` `charpoly` `trace` `transpose` `solve` `mul` `factor` `expand` `simplify` `subst`

- 矩阵写法：`a,b;c,d` 或 `[[a,b],[c,d]]`，行用分号、元素用逗号；
- `solve: A=1,2;2,4 | b=1;2` 解线性方程组，能识别无解与无穷多解（用 `t1` 表示自由变量）；
- `det` 会额外给出因式分解结果，`charpoly` 给出特征多项式及其分解；
- 自动归一化全角符号（`×` `÷` `−` `（）` `，` `；`）、全角数字与 `lambda` 之类的希腊字母名；
- 结果以 LaTeX 显示，可复制；每条命令独立报错，错误信息为中文。

设置 → 特殊 Agent 里有「查看工具示例效果」，可以直接看到这个引擎算出来的真实结果，不经过模型。

已知边界：多变量一般因式分解只覆盖常见可约型；符号行列式 ≤ 6 阶、符号求逆/秩 ≤ 4 阶；符号矩阵不支持行最简形；均会返回明确的中文错误而不是崩溃。

## 3. 自动跟随输出开关

设置 → 对话 → 「自动跟随输出」：

- 开启（默认）：思考与回答持续输出时，页面自动贴到底部；
- 关闭：输出期间页面完全不动，只有你自己滑到底、或点输入框上方的「到底部」，页面才移动。

配合 1.4.1 改造过的滚动逻辑（只在用户本来就在底部时才补齐差值），上滑阅读历史回答时不会再被流式输出拽回去。

## 4. 新解答风格：多调用数值检验

Agent 预设的解答风格里新增第 9 个选项：

- **多调用数值检验**：容易算错的环节主动调用计算类工具实际算一遍，最终回答里说明验证了哪些量，不把没验证过的结果当成已验证。
- 该风格只在开启「计算器 Agent」或「线性代数计算器 Agent」时可选；未开启时选项置灰并提示先到设置里开启。
- 与「图文并茂」（需要绘图 Agent）的处理方式一致。
