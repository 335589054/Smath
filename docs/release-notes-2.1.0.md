## 安装

同签名直接覆盖安装即可，本地数据（会话、预设、Key、用量统计）会保留：

或把 APK 传到手机上点击安装（需要允许「安装未知来源应用」）。

## 新增

### 1. 绘图工具支持参数方程

新增绘图命令：

```
[$$paint_start$$]
axes(-6, 6, -4, 4)
color(红)
param("3*cos(t)", "2*sin(t)", 0, 6.2832, 800)
[$$paint_end$$]
```

- `param(x表达式, y表达式, t起点, t终点, 采样数[, 轴编号])`，自变量固定写 `t`。
- 采样数就是绘制精度：40–3000，默认 600；曲线打结或尖点处取大一些。
- 会主动拒绝「画不准」的图：表达式过长（x、y 合计超过 180 字符）、运算过多（超过 60 个）、区间内取不到实数、数值爆到 1e5 以上，都会给出中文提示并改用文字或简单函数图像替代，不会硬画一条错误的曲线。

### 2. 后台继续生成

回答生成期间切到后台、锁屏或切到别的应用，请求会继续跑，通知栏显示「正在回答：<会话名>」。回到 Smath 就能看到已经生成好的内容。

这依赖前台服务（`dataSync` 类型），首次使用会看到一条常驻通知，属于正常现象。

### 3. 可选图片压缩

设置 →「对话」→「压缩图片后再上传」，默认开启。

- 开启：长边压到 1024、JPEG 质量 70，明显省 token，公式和题目照片仍然看得清。
- 关闭：保留长边 1600、质量 88，适合细节多的截图。
- 只影响新上传的图片，历史会话里的图片不受影响。

### 4. Token 消耗统计

- **对话页**：输入框下方一行小字，例如 `上下文 1.6 K / 131 K · 1.2%　缓存命中 81%`。
  - 前面是本轮请求的上下文占用（token）与模型窗口大小、占用比例。
  - 后面是服务商返回的缓存命中率（命中 token / 输入 token；服务商不返回时显示 0%）。
  - 读数优先用本轮实时数据，没有则回退到该会话最近一次请求的数值。
- **设置页**：「Token 消耗」分区按服务商 / 模型分别累计，单位 M。
  - 每行显示总量、输入、输出、缓存命中。
  - 顶部显示累计总量；「清空」可重置统计。
  - 统计只存在本机，不上传；换 Key 或换服务商不会清空历史，需要时可手动清空。

用量统计依赖服务商返回 `usage` 字段。请求里已经带上 `stream_options: { include_usage: true }`，兼容 OpenAI 与 DeepSeek 两种缓存字段写法（`prompt_tokens_details.cached_tokens` / `prompt_cache_hit_tokens`）。

## 修复

- 部分 OpenAI 兼容服务商在每个流式分片里返回 `"usage": null`，导致解析报 `JsonNull cannot be cast to JsonObject` 并中断回答；现在按「字段为空就当没有」处理，只有真正带数字的分片才计入统计。
- 用量读数行插入时曾把输入框的闭合括号吃掉导致整文件编译失败，已复原后按精确位置重做，无残留。
- 对话页的用量读数现在只要在会话里就显示：还没请求过时显示 `上下文 0 / 131 K · 0%` 与 `缓存命中 —`，不再因为「没有数字」而整行消失。
- 设置页「清空」用量统计加了二次确认（说明会清零哪些数据），避免误触。
- 长对话向上翻动时会突然跳到上一条消息开头：原因是消息里的 Markdown/KaTeX 用 WebView 渲染，条目滑出屏幕被回收后重新组合时高度从 20dp 重新长起来，LazyColumn 就跟着重新定位。现在把每条消息的渲染高度按消息 id 缓存，回收后再出现直接以最终高度布局，翻动时不再跳。
- 统计已确认跨进程持久化：连续发起对话后强制退出再打开，累计值仍在。

## 已知限制

- 上下文窗口大小是按模型名估算的（DeepSeek / GPT-6 / Gemini 记 1 M，o3/o4 记 200 K，gpt-4o 记 128 K，qwen 记 131 K，其余记 128 K）。自定义模型名对不上时会按 128 K 估算，只影响百分比显示，不影响实际请求。
- 缓存命中率由服务商决定；部分服务商（例如某些第三方聚合）根本不返回该字段，此时显示 0%。
- 参数方程只支持 `t` 一个自变量，不支持极坐标专用写法（可以用 `param` 手动写 `r*cos(t)` / `r*sin(t)`）。
- 后台生成受系统省电策略影响，极端省电模式下通知里会提示，但无法保证无限期存活。
